## Part 1: Prediction markets

### New findings since 2026-10-16 (read first)

1. **Kalshi Data Terms of Use: possibly restrictive, scope unverified (S; official PDF not fetched).**
   - Locator: `kalshi-public-docs.s3.amazonaws.com/kalshi-data-terms-of-service.pdf`. This is a cloud-bucket host, which agents do not fetch.
   - What search summaries quote it as saying:
     - access is limited to "personal use for non-commercial purposes";
     - without prior written consent, use excludes "the development of any software program, including … training a machine learning or artificial intelligence system" and "providing archived or cached data sets";
     - "scraping or compiling" is prohibited without written authorization.
   - A third-party review (S) says Developer Agreement §3 limits API use to facilitating a member's own trading, and §3.1 bars sharing API data with third parties.
   - **Which surface these terms govern is not established.** The surfaces are the website, the official API, PMV capture, third-party archives, and upstream reference data.
     - The Kalshi documentation says API use binds the user to the Developer Agreement (G).
     - Whether the Data Terms also govern API data depends on the agreement chain, which has not been read.
   - Every Kalshi surface PMV would use is therefore NEEDS_LICENCE_CLARIFICATION, not PROHIBITED_FOR_INTENDED_USE. Master inventory §2 gives the status surface by surface.
2. **Polymarket licensing (S).** Polymarket's institutional page says "Capital Markets Entities" must consult Polymarket and ICE before consuming Polymarket data "whether sourced from the API or on-chain, in raw, derived, aggregated, or anonymized form" (contact `data-licensing@polymarket.com`). Whether a private own-account trader is covered is UNKNOWN. On-chain data is therefore not licence-free by assumption.
3. **Polymarket US (S).**
   - There is a public no-key REST gateway (`gateway.polymarket.us`) for markets, book, BBO, settlement, and price history.
   - The WebSocket needs a KYC'd key. There is no public trade tape.
   - The rulebook (2026-08-05) prohibits redistribution and calls the data proprietary to PMUS.
4. **BigQuery Polygon (FS and S).**
   - The legacy `public-data-finance.crypto_polygon` "has not been updated since 2024-09-01" (FS, `github.com/blockchain-etl/polygon-etl`). The public-datasets README still lists it as operational (FS), so the two pages CONFLICT.
   - Google Cloud Blockchain Analytics lists two maintained Polygon datasets (S): "Polygon Blockchain (Preview)", updated hourly, and "Polygon Mainnet (Community)", updated within minutes. Both have `blocks`, `transactions`, `logs`, and a `decoded_events` table that covers "popular event types".
   - Whether Polymarket `OrderFilled` and resolution events are decoded is UNKNOWN, so expect to decode raw logs with the ABI. Coverage start is UNKNOWN. The datasets fall under Pre-GA terms.
5. **Kalshi depth (S).** The archive reaches back to about 2021-06. The live/historical cutoff lags about 2–3 months behind now, which reads as a lag rather than a retention limit. Candles come at 1, 60, or 1440 minutes only.
6. **Kalshi gold (S).**
   - KXGOLD15M launched about August 2026, with 96 windows per weekday. It settles YES if the "Pyth GOLD" 1-minute close at the end is at or above the close at the start.
   - Polymarket gold is daily only, settling on Pyth `Metal.XAU/USD`.
   - Kalshi gold history is therefore about 2.5 months, much of it probably still in the live tier.
7. **Polymarket API changes (S).** Data API v1 reportedly retires on 2026-10-24 (third party). `/v2/prices-history` keeps 3-hour data permanently from July 2026.
8. **Kalshi Research feed via DoubleZero Edge (S).** Launched 2026-08-12, it covers sports and crypto perpetuals, not 15-minute binaries. History is "planned".
9. **pmxt archive (S).**
   - CC BY 4.0 is claimed.
   - v1 runs 2026-02-21 to 2026-04-16 and missed about half of markets.
   - v2 starts 2026-04-13T19Z and may have stopped about 2026-08-09 (unconfirmed).
   - The hosted API has stricter terms.
